# Как устроена генерация упражнений

Упражнения не берутся из «сгенерируй 10 заданий по теме X». Промпт собирается
из четырёх модулей в `lib/`, и каждый отвечает за свой слой качества.

| Модуль | За что отвечает |
| --- | --- |
| `grammar-rules.js` | 45 грамматических тем: правило, дизайн задания, дистракторы, запреты |
| `exercise-formats.js` | каталог из 9 форматов заданий с разобранными примерами |
| `quality-rules.js` | общие правила: субстанция вариантов, качество дистракторов, список брака |
| `exercise-prompt.js` | уровни A1–C1 и сборка финального промпта |
| `exercise-validation.js` | проверка ответа модели: что промпт не гарантирует — проверяет код |

## Главная проблема, которую решает система

Типовой плохой вопрос выглядит так:

```
Er versucht, den Bahnhof ___ finden.
A) zu     B) –     C) zum     D) um zu
```

Это не упражнение. Тот, кто знает конструкцию, узнаёт ответ мгновенно;
тот, кто не знает, — гадает из четырёх. Проверяется не владение
`Infinitiv mit zu`, а узнавание частицы.

Правильная версия той же темы:

```
Sein Zug fährt um sechs. (vorhaben – früh aufstehen)
A) Er hat vor, morgen früh aufzustehen.      ← верно
B) Er hat vor, morgen früh zu aufstehen.
C) Er hat vor, morgen früh aufstehen zu.
D) Er hat vor, morgen früh aufstehen.
```

Варианты — целые предложения из одного и того же материала, различаются
только положением `zu`. Угадать по длине или по «единственному осмысленному
варианту» нельзя.

## Правило субстанции

Формулируется в `quality-rules.js` и звучит так: **вариант ответа должен
содержать всю целевую структуру, а не один элемент из неё.**

| Тема | Что должно быть в варианте | Что запрещено |
| --- | --- | --- |
| Infinitiv mit zu | вся инфинитивная группа или предложение целиком | `zu / – / zum / um zu` |
| Падежи, артикли, склонение прилагательных | вся именная группа: `ihrer neuen Kollegin` | `dem / den / der / des` |
| Perfekt, Passiv, Futur, модальные | весь глагольный комплекс, лучше двойным пропуском | одно причастие |
| Порядок слов, придаточные, рамка | всегда целые предложения | обрывки |

Единственное исключение: когда целевое явление действительно и есть одно
слово — выбор союза (`als / wenn / wann`), значение модального глагола,
предлог при фиксированном управлении. Тогда решение должно нести контекст:
мини-диалог или однозначные слова-сигналы, и предложение не короче восьми слов.

## Форматы заданий

Вместо одного «вставь пропуск» — девять форматов. Для каждой темы в
`grammar-rules.js` перечислено, какие из них подходят; в промпт попадают
только они, вместе с разобранными примерами.

| id | Формат | Что даёт |
| --- | --- | --- |
| `satzvarianten` | выбор из четырёх целых предложений | снимает угадывание по длине |
| `umformung` | преобразование (актив → пассив, презенс → претерит) | проверяет продуктивное владение |
| `verbindung` | соединить два предложения в одно | падеж + порядок слов сразу |
| `fehlerkorrektur` | найти и исправить одну ошибку | вариант «не исправлено» — сильный дистрактор |
| `dialog` | мини-диалог, решает контекст | единственный честный способ проверять значение |
| `mehrfachluecke` | два пропуска, матрица 2×2 | половинное знание видно в статистике |
| `wortstellung` | собрать предложение из частей | целые предложения в вариантах |
| `bedeutung` | минимальная пара, все варианты грамматичны | проверяет понимание, а не форму |
| `luecke` | классический пропуск, но со всей структурой | базовый формат для падежей и форм |

В блоке из 10 заданий требуется минимум 4 разных формата, не больше 4 заданий
одного формата и минимум 2 задания из сложных форматов (`umformung`,
`verbindung`, `fehlerkorrektur`, `bedeutung`).

## Что проверяет код, а не промпт

`exercise-validation.js` отбраковывает то, что модель всё равно иногда
присылает:

- не ровно 4 варианта, пустые или повторяющиеся варианты;
- пропуск `___` внутри варианта ответа;
- оборванное предложение (заканчивается на `...`);
- расхождение между номером правильного ответа и его текстом — модель обязана
  продублировать ответ дословно, и это сверяется;
- **нарушение правила субстанции**: если все четыре варианта короче минимума
  для этой темы, задание отклоняется;
- варианты, отличающиеся по длине более чем в 5 раз;
- дубли внутри блока и повтор уже выданных заданий;
- перекос по форматам: лишние задания одного формата уходят в конец очереди.

Причины отбраковки пишутся в лог — по ним видно, на чём именно спотыкается
модель:

```
[Infinitiv mit zu B1] 8/12 Aufgaben übernommen; aussortiert: Füllwort-Optionen: Thema verlangt mindestens 3 Wörter je Option; doppelte Optionen
```

Сервер запрашивает на 4 задания больше, чем нужно, — с запасом на отбраковку.

## Уровни

`exercise-prompt.js` разворачивает «уровень A2» в конкретные ограничения:
длина предложения, разрешённые и запрещённые структуры, пласт лексики,
замечание о подходящих форматах. Без этого «A2» для модели — пустой ярлык.

## Как добавить тему

1. Добавить название в `GRAMMAR_TOPICS` в `public/js/questions.js`.
2. Добавить запись в `GRAMMAR_RULES` в `lib/grammar-rules.js` с полями
   `rule`, `design`, `formats`, `traps`, `avoid`.
3. Если целевая структура больше одного слова — внести тему в `PHRASE_TOPICS`
   или `SENTENCE_TOPICS` в `lib/exercise-validation.js`.
4. `npm test` — тест проверяет, что у каждой темы клиента есть правила и что
   все указанные форматы существуют.

Если клиент присылает название в ASCII-транслитерации (`Praeteritum`,
`Relativsaetze`), оно всё равно найдётся: `resolveTopic` нормализует умлауты и
знает список синонимов.

## Тесты

```
npm test
```

Проверяются: полнота правил, разрешимость всех тем клиента, корректность
примеров в каталоге форматов, отбраковка примитивных заданий и сохранность
допустимых однословных заданий.
