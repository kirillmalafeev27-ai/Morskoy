# Деплой

Приложение — обычный Node-сервер: раздаёт статику из `public/` и держит
API генерации упражнений. Никакой сборки фронтенда нет, поэтому деплой
сводится к «поставить зависимости и запустить `node server.js`».

## Northflank

### 1. Создать сервис

В проекте Northflank: **Create new service → Combined service** (сборка и
запуск в одном), подключить этот репозиторий и ветку.

### 2. Настройки сборки

| Поле | Значение |
| --- | --- |
| Build type | **Dockerfile** |
| Dockerfile path | `/Dockerfile` |
| Build context | `/` |

`Dockerfile` в корне репозитория уже готов: ставит только production-зависимости
через `npm ci --omit=dev`, запускается от непривилегированного пользователя
`node` и содержит `HEALTHCHECK` на `/healthz`.

Альтернатива — сборка через **Buildpack**: она тоже работает, потому что
`package.json` больше не тянет нативных пакетов. Но Dockerfile даёт
воспроизводимый результат, поэтому он предпочтительнее.

### 3. Порт и публичный адрес

В разделе **Ports & DNS** добавить порт:

| Поле | Значение |
| --- | --- |
| Port | `3000` |
| Protocol | `HTTP` |
| Public | включить (иначе сервис доступен только внутри проекта) |

Northflank не подставляет переменную `PORT` сам, поэтому в `Dockerfile` она
задана явно: `ENV PORT=3000`. Если понадобится другой порт — задайте `PORT`
в переменных окружения и укажите то же число в Ports & DNS.

### 4. Health check

В разделе **Health checks** добавить:

| Поле | Значение |
| --- | --- |
| Type | `HTTP` |
| Path | `/healthz` |
| Port | `3000` |

Эндпоинт отвечает `{"ok":true}` и не зависит от внешних ключей, так что
сервис считается живым даже без настроенной генерации.

### 5. Переменные окружения

Обязательная одна:

| Переменная | Зачем |
| --- | --- |
| `AITUNNEL_API_KEY` | ключ AI Tunnel для генерации упражнений. Без него `/api/generate-questions` отдаёт `503`, игра при этом запускается, но вопросы не приходят |

Необязательные:

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `AITUNNEL_MODELS` | `gpt-5.4,gpt-5.2,gpt-5,gpt-5-mini,gpt-4o,gpt-4o-mini` | список моделей через запятую; перебираются по порядку, пока одна не ответит |
| `AI_BASE_URL` | `https://api.aitunnel.ru/v1` | другой OpenAI-совместимый эндпоинт |
| `OPENAI_API_KEY` | — | используется, если `AITUNNEL_API_KEY` не задан |
| `ELEVENLABS_API_KEY` | — | озвучка немецких фраз в аудиорежиме; без неё `/api/tts` отдаёт `503` |
| `ELEVENLABS_VOICE_ID` | `21m00Tcm4TlvDq8ikWAM` | голос |
| `ELEVENLABS_MODEL_ID` | `eleven_turbo_v2_5` | модель синтеза |
| `TTS_CACHE_LIMIT` | `180` | сколько озвученных фраз держать в памяти |

### 6. Проверка после деплоя

```
curl https://<адрес-сервиса>/healthz
# {"ok":true}

curl https://<адрес-сервиса>/api/quiz/status
# {"ok":true,"generationConfigured":true,"ttsConfigured":false,"models":[...]}
```

`generationConfigured: false` означает, что `AITUNNEL_API_KEY` не долетел до
контейнера — проверьте переменные окружения сервиса.

## Локальный запуск

```
npm ci
AITUNNEL_API_KEY=... npm start
# http://localhost:3000
```

Тесты правил генерации:

```
npm test
```

## Что было исправлено для деплоя

- Убран неиспользуемый `@anthropic-ai/sdk`: код давно ходит в AI Tunnel через
  `fetch`, а пакет тянул лишние мегабайты в каждую сборку.
- Убран `fbx2gltf` из `devDependencies`. Это нативный пакет, который на сборке
  скачивает и компилирует бинарник; при `npm install` он ронял сборку целиком.
  Модели давно лежат в репозитории уже в формате `.glb`, конвертер в рантайме
  не нужен.
- `package-lock.json` пересобран под новый список зависимостей, иначе
  `npm ci` падает с рассинхроном.
- Сервер слушает `0.0.0.0`, а не только loopback — иначе health check
  платформы не достучится до контейнера.
- `public/LowPolyDungeon_FBX.zip` (6 МБ исходников моделей) исключён из образа
  через `.dockerignore`.
